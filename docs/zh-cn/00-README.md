## 系统架构简介

本系统由三个核心组件组成，先了解它们的关系，后续章节会更容易理解：

```text
+----------+     HTTP 管理请求      +----------+
|  控制台   |  ------------------>  |  API Server  |
| (本手册)  |   (浏览器:8183)       |  (管理后台)   |
+----------+                       +----------+
                                          |
                                          | 下发配置
                                          v
+----------+     HTTP/HTTPS 请求     +----------+     转发请求      +----------+
|  客户端   |  ------------------>  |  BFE 数据面  |  ------------>  | 后端模型服务 |
| (调用方)  |   (携带 API Key)       | (转发引擎)   |               | (如 vLLM)  |
+----------+                       +----------+                 +----------+
```

| 术语 | 通俗理解 | 作用 |
| ------ | -------- | ------ |
| **控制台** | 你现在正在看的 Web 管理界面 | 管理员通过浏览器配置资源、路由、权限 |
| **BFE / 数据面** | 实际转发请求的"网关引擎" | 接收客户端请求，做鉴权、限流、配额检查，再转发给后端模型服务 |
| **API Server** | 控制台背后的管理后台服务 | 处理控制台的保存、查询请求，把配置同步给数据面 |
| **conf-agent** | 部署在数据面机器上的配置同步助手 | 负责把 API Server 的配置下发到 BFE，让规则生效 |

> **一句话记住**：控制台是"配置后台"，BFE 数据面是"请求转发器"。你的 curl 请求发向 BFE，管理操作在控制台做。

## 约定说明

- 截图均为真实环境截取，示例数据（集群名 `demo-cluster`、服务商 `demo-provider`、组织 `dev-team` 等）与 13 章保持一致；
- 文中「→」表示菜单层级，如 资源管理 → 模型服务商；
- 必填字段以 `*` 标注；
- 控制台地址默认为 `http://<控制台IP>:8183`，默认管理员账号 `admin` / `admin`（见 [01 章](01-login-and-user.md)），建议首次登录后及时修改；
- **控制台 IP 怎么填**：单机本地部署用 `127.0.0.1`；远程服务器部署用浏览器地址栏中的 IP 或域名（如 `192.168.1.10`）。
- **部署文档**：[AI Gateway Web 部署](deploy.md)、[AI Gateway API 部署](https://github.com/rainway-ai-gateway/ai-gateway-api/blob/develop/docs/zh_cn/deploy.md)。

## 模块全景

```text
资源管理 ─ AI业务集群（引用服务商，配置转发与治理策略）
        ├ 模型定价（模型价格维护与费用核算）
        ├ 模型服务商（实例池 + 协议 + 模型 + Keys）
        └ EPP调度（EPP 实例池与集群调度分配）
路由管理 ─ 路由表（Global / Entity / API-Key 三级优先级）
功能增强 ─ AI缓存规则（应答缓存开关与缓存键规则）
        ├ 流量镜像规则（生产请求副本异步发往镜像集群，用于双跑验证）
        ├ 意图配置（问题集与置信度门控阈值）
        └ AI上下文压缩（压缩规则与全局设置）
消费者管理 ─ API Key 管理（调用凭证）
          ├ 批量任务（provider 原生批量任务的管控）
          └ Entity管理（类型 / 组织；配额、限流、模型访问控制）
系统安全 ─ 密钥收敛（库内敏感密钥的批量重加密 / 解密）
数据报表 ─ 总览指标、时序图表、维度排行与日志明细
用户管理 ─ 控制台账号与 Token
操作日志 ─ 写操作自动记录，只读查询
```

> 菜单「Entity管理」是一项，手册拆为两章：[07 Entity 类型](07-entity-type.md)（分类维度）与 [08 Entity 组织](08-entity.md)（组织本身，配额与限流的挂载点）。

## 请求是怎么被处理的？

当客户端发起一次调用时，请求在系统内的处理顺序如下：

```text
客户端请求
    │
    ▼
┌─────────────┐
│ 1. 鉴权      │  ← 检查 API Key 是否有效
└─────────────┘
    │
    ▼
┌─────────────┐
│ 2. 模型访问控制 │  ← 检查该 Key / 组织是否允许访问这个模型（不通过 403）
└─────────────┘
    │
    ▼
┌─────────────┐
│ 3. 限流检查   │  ← 检查是否触发 TPM / RPM / 并发限制（触发 429）
└─────────────┘
    │
    ▼
┌─────────────┐
│ 4. 配额扣减   │  ← 扣减 Token 配额（余额不足则拒绝）
└─────────────┘
    │
    ▼
┌─────────────┐
│ 5. 路由匹配   │  ← 按 API-Key > Entity > Global 优先级匹配规则
└─────────────┘
    │
    ▼
┌─────────────┐
│ 6. 转发请求   │  ← 把请求发给对应的业务集群（经所属服务商实例池）
└─────────────┘
```

> 记住这个顺序：**鉴权 → 模型权限 → 限流 → 配额 → 路由 → 转发**。任何一步失败都会立即返回错误，不会继续往后走。
