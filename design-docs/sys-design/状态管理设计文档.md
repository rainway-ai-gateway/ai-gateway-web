# AI Gateway Web 状态管理设计文档

## 1. 设计目标

- 以最小化状态管理满足会话、导航与全局共享需求。
- 避免引入 Vuex，降低学习成本与样板代码。
- 用户会话持久化到 `localStorage`，刷新页面后仍可恢复。

## 2. 技术选型

| 能力 | 说明 |
|------|------|
| `Vue.observable` | 创建响应式状态对象，供任意组件读取。 |
| `localStorage` | 持久化用户会话与导航元数据。 |
| 纯对象 store | `src/utils/store.js` 导出包含状态与方法的对象。 |

## 3. 状态结构

`src/utils/store.js` 中定义：

```js
state: Vue.observable({
  user: null,            // 当前登录用户
  meta: null,            // 后端导航元数据
  breadcrumbTitle: '',   // 覆盖面包屑标题（如路由表详情）
  breadcrumbRouteName: ''
})
```

### 3.1 `user`

结构：

```js
{
  name: string,        // 用户名
  sessionKey: string,  // 会话密钥
  role: string         // 'system_admin' | 'system_admin_readonly'
}
```

- 来源：登录接口返回，经 `setUserData` 转换后写入；`role` 由 `src/utils/role.js`
  的 `resolveRole` 归一化（登录响应本身只有 `role`；升级/切换环境后浏览器里可能
  残留旧格式 `{is_admin}`，`true` 视为 `system_admin`）。
- 持久化：写入 `localStorage.user`。
- 读取：`getUser()` 优先从内存读取，内存无值时从 `localStorage` 解析，并对
  旧版本写入的 `{name, sessionKey, is_admin}` 就地补出 `role`。

### 3.2 `meta`

- 来源：后端 `meta` 接口（`GET /open-api/v1/meta`）。
- 用途：提供导航树、产品线等权限相关元数据。
- 仅保存在内存中，刷新后重新拉取。

## 4. Store API

| 方法 | 说明 |
|------|------|
| `getUser()` | 获取当前用户对象（`role` 经 `resolveRole` 归一化，兼容本地残留的旧格式 `is_admin`）。 |
| `setUserData(newVal)` | 登录成功后设置用户，并持久化到 `localStorage`。 |
| `removeUserData()` | 清除用户会话，用于登出或 401 处理。 |
| `getMeta()` | 获取导航元数据。 |
| `setMeta(newVal)` | 设置导航元数据。 |
| `getNav()` | 获取 `meta.nav`。 |
| `getNavRoot()` | 按角色取菜单树根：`system_admin` → `meta.nav.admin`、`system_admin_readonly` → `meta.nav.admin_readonly`，缺省回退 `admin`。 |
| `isReadonly()` | 当前登录态是否为只读系统管理员。 |
| `findNav(routeName)` | 在导航树中按 `id` 查找节点。 |
| `getLoginRoute()` | 返回登录路由 `name`（`LoginPassword`）。 |
| `setBreadcrumbTitle(title, routeName)` | 覆盖面包屑标题（路由表详情页使用）。 |
| `getBreadcrumbTitle()` | 读取覆盖的面包屑标题。 |

## 5. 鉴权流程

`src/utils/authorize.js` 在路由守卫中被调用：

```
1. 检查 store.meta
   └─ 为空 → 请求 GET /open-api/v1/meta
             └─ 成功 → 存入 store.meta
             └─ 失败 → 不中断导航；后续跳过菜单校验放行（权限由服务端接口把关）

2. 目标路由为 LoginPassword → 放行

3. 检查用户登录态
   └─ 未登录（含 localStorage 数据不可解析，已自动清空）→ 返回登录路由

4. 检查角色（role）
   └─ roleIssue(user) 非空 → 按原因返回：字段缺失（前后端版本不一致）→ 'roleVersionMismatch'（提示版本不一致，确定=刷新页面）；有角色字段但不可用 → 'illegalAccess'（提示无控制台访问权限，确定=回登录页）
   └─ 本地残留旧格式登录态（只有 is_admin）时按 is_admin=true → system_admin 回退，避免首次打开被误判

5. 检查目标路由是否在导航树中（meta 未取到时跳过）
   └─ 不在 → 返回登录路由

6. 放行
```

## 6. 会话生命周期

### 6.1 登录

- `loginPassword.vue` 调用 `POST /open-api/v1/auth/session-keys`。
- 成功后调用 `store.setUserData(response)`。
- 跳转至首页 `product.home`。

### 6.2 请求鉴权

- `request.js` 拦截器自动从 `store.getUser()` 读取 `sessionKey`。
- 注入请求头：`Authorization: Session <sessionKey>`。

### 6.3 登出/401

- 收到 401 响应时，`request.js` 调用 `store.removeUserData()`。
- 弹出错误提示，并跳转登录页。
- 402 保留登录态，仅提示无权限。

## 7. 全局状态访问

- 在 `main.js` 中将 store 挂载到 Vue 原型：

```js
Vue.prototype.$store = store;
```

- 组件中可通过 `this.$store` 读取状态或调用方法。
- 但建议仅用于读取 `user` 与 `meta`，业务状态应下沉到模块组件内部。

## 8. 设计约束

1. **禁止在 store 中保存业务数据**：store 只保存会话与导航元数据。
2. **业务状态优先提升模块容器**：复杂模块状态由模块容器组件管理，子组件通过 props/emit 交互。
3. **敏感信息脱敏**：`sessionKey` 保存在 `localStorage` 中，需注意 XSS 风险；避免在模板中直接渲染。
4. **导航元数据由后端驱动**：前端不硬编码菜单，菜单变更通过后端 `meta` 接口生效。
