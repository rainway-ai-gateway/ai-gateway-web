# RouteTable 模块细节设计

## 1. 模块定位

`RouteTable` 统一管理三级路由表：**Global**、**Entity**、**API-Key**。列表页分页展示所有路由表；进入详情后以内联方式编辑该表下的路由规则。规则支持加权 `targets` 与降级 `fallbacks`，条件表达式由 `Expression` 组件编辑（面板与 `design-docs/bfe-condition-primitive-define/` 全量对齐；路由为请求阶段匹配，传入 `hide-groups="['response']"` 隐藏响应侧原语）。

已废弃的 `modules/Routes`、`modules/AIRouteRules` 不再使用；路由 `name` 仍为 `AdvanceRouteRule.list`，路径为 `/route-tables`。

## 2. 路由与入口

| 路由 | name | 组件 | 说明 |
|------|------|------|------|
| `/route-tables` | `AdvanceRouteRule.list` | `modules/RouteTable/index.vue` | 路由表列表；query `type` / `owner` / `rule` 可直达详情。 |

内部组件：

- `RouteTable/index.vue`：列表 + 详情切换。
- `RouteTable/components/RouteRules.vue`：某张表的规则列表、启停、提交。
- `RouteTable/components/RuleForm.vue`：单条规则表单（条件、targets、fallbacks）。
- `RouteTable/components/RuleView.vue`：单条规则只读详情。

## 3. 页面结构

### 3.1 列表页

- `pageTable` 开启 `server-pagination`，请求 `GET route-tables`（`page` / `page_size` + type/owner/enabled 筛选）。
- 列：类型（Global / Entity / API-Key）、归属、启用状态、操作（查看、启停）。
- Entity 类型的 owner 通过 `GET entities` 解析为名称。

### 3.2 详情 / 规则编辑

- 进入详情后覆盖面包屑（`store.setBreadcrumbTitle`）。
- `RouteRules` 支持查看 / 编辑；未保存离开时二次确认。
- 行内新增、编辑、查看、删除规则；整表提交一次生效。

### 3.3 规则次序与拖拽排序

- **次序即匹配优先级**：同一路由表内规则按 `rules` 数组顺序逐条匹配，命中第一条即停止，更具体的规则必须排在前面。次序**只由提交时数组的元素位置承载**，接口无独立的次序字段（见 `design-docs/api-define/OpenAPI接口定义/global-route-rules.md` §1）。
- **入口**：仅**编辑模式**下可拖拽（`pageTable` 传 `:draggable="mode === 'edit'"`），查看模式无拖拽；编辑模式下列表下方显示一行提示（i18n key `route.dragToChangeOrder`，已存在，本轮起被引用）。
- **落点语义**：被拖拽行**插入到落点行的原始位置**——先从数组中移除，再按落点行的原始下标插入；不是「拖到目标之后」，也不是交换两行。
- **处理函数契约**：`RouteRules.onRuleDragDrop(startIndex, endIndex)` 在 `cloneDeep(this.rules)` 的副本上操作（不就地改数组），改完赋值回 `rules` 后**必须调用 `refreshRuleIndex()`**——行内「编辑 / 删除」按钮依赖 `row.index` 定位规则，次序变化后不重新编号会改错行；提交前 `buildPayload()` 会剔除 `index` / `_index` / `_rowKey`。
- **`pageTable` 契约**：`draggable: Boolean`（默认 `false`，未开启时行为与变更前完全一致）+ `dragDrop(startIndex, endIndex)` 事件，两个下标是**被拖拽行与落点行在 `tableData` 原始数组中的下标**，不是渲染 / 筛选 / 排序后的展示位置。组件内部以 `showSrcIndex` / `cloneShowSrcIndex` / `pageSrcIndex` 维护该映射，并在 `tableData` 变化、列搜索、列排序、分页切片时同步维护；展示顺序无法映射回原始数组时（列 `customSort` 由父组件接管排序）不派发事件，即拖拽静默不生效。详见 `design-docs/sys-design/组件与复用设计文档.md`。
- **已知限制**：拖拽仅限当前页内（`pageTable` 客户端分页、默认 20 条 / 页）；拖拽后列表回到第 1 页且列搜索 / 列排序状态被重置（`pageTable` 对 `tableData` 变化的既有行为，与新增 / 编辑 / 删除一致）；列头排序只改变展示、**不改变生效次序**。
- **列排序 / 列搜索下的拖拽仍准确**：本模块规则列使用 `sortable: 'custom'`（iView 不做内部排序，排序由 `pageTable` 自己完成），`pageTable` 会同步排序下标映射，因此叠加列搜索或列排序后，拖拽移动的仍是用户看到的那两行。仅当列声明 `customSort`（排序完全交给父组件接管，本仓库当前无此类列）时映射无法还原，`pageTable` 才不派发事件。
- **「提交并生效」置灰策略**：编辑模式下未做任何改动（`isDirty` 为假）时，「提交并生效」按钮 `:disabled="!isDirty"` 置灰不可点；`isDirty` 含启用状态变化与规则数组变化两部分。
- **行内「复制」**：编辑模式行操作在「编辑」「删除」之间提供「复制」——`onCopyRule(row.index)` 深拷贝当前行并剔除 `index` / `_index` / `_rowKey`，新名称取 `原名-copy`（名称超长截断到 64 字符、重名时自动升级为 `-copy2` / `-copy3`…），插入到源行**下一行**，随后 `refreshRuleIndex()` 重新编号。
- **列表默认启用筛选**：路由表列表的「状态」筛选默认「启用」——列定义带 `searchValue: 'true'`，`searchParams` 初始值为 `{ enabled: 'true' }`，首次请求即只拉取已启用的路由表；切换 / 清空筛选后恢复全量。

## 4. 组件清单

| 组件 | 职责 | 关键 Props | 事件 |
|------|------|------------|------|
| `index.vue` | 列表分页、打开详情、启停 | — | — |
| `RouteRules.vue` | 某张表的规则 CRUD 与提交 | `type`、`owner`、`ownerName`、`initialData`、`initialFilter` | `close`、`submit` |
| `RuleForm.vue` | 单条规则表单 | 规则数据、集群列表 | `submit` |
| `RuleView.vue` | 单条规则只读 | `rule` | — |

## 5. 表单字段与校验

规则字段统一 snake_case，与 OpenAPI 对齐：

| 字段 | 校验 | 说明 |
|------|------|------|
| `name` | 必填；同表内不重复 | 规则名称。 |
| `cond` | 表达式校验 | 匹配条件；`Expression` 组件编辑。校验失败时**仅**外层 FormItem 展示错误，组件内不重复渲染 error 文本。 |
| `targets[]` | `cluster_name` 必填；`weight` 之和为 100 | 转发目标；`model` 可空表示透传。 |
| `fallbacks[]` | 可选 | 降级目标；无 weight。 |
| `(cluster_name, model)` | `targets` 内部、`fallbacks` 内部、以及两者之间均不可重复 | 交叉去重。 |

表达式 `body` 维度新增 `req_body_json_prefix_in(json_path, value_prefix_list, case_insensitive)`，用于按请求体 JSON 字段前缀匹配（如 `req_body_json_prefix_in("model", "openrouter/", false)`）。

## 6. 数据流

```
RouteTable/index.vue
    ├─ GET /route-tables → 分页列表
    ├─ 查看 → RouteRules.vue
    │     ├─ Global：GET/PUT /global-route-rules  （body: { enabled, rules }）
    │     ├─ Entity：GET/PATCH /entities/{id}     （body: { route_rules: { enabled, rules } }）
    │     └─ API-Key：GET/PATCH /api-keys/{id}    （同上嵌套 route_rules）
    │           └─ RuleForm / RuleView
    └─ 列表启停：拉取完整规则后 PUT/PATCH，只改 enabled
```

## 7. OpenAPI 消费映射

| 组件 | 方法 | 相对 URL | 说明 |
|------|------|----------|------|
| `index.vue` | `GET` | `route-tables` | 分页列表。 |
| `index.vue` | `GET` | `entities` | 解析 Entity 名称。 |
| `RouteRules.vue` | `GET` | `clusters` | 目标/降级集群。 |
| `RouteRules.vue` | `GET` / `PUT` | `global-route-rules` | Global 表。 |
| `RouteRules.vue` | `GET` / `PATCH` | `entities/{id}`、`api-keys/{id}` | 嵌套 `route_rules`。 |
| `RuleForm.vue` | `GET` | `clusters` | 集群与模型下拉。 |

## 8. 边界情况

- 路由 `name` 保持 `AdvanceRouteRule.list`，与后端导航元数据 `id` 一致，路径已从 `/ai-rule` 改为 `/route-tables`。
- 启停切换必须带上完整 `rules`，避免后端把规则清空。
- 从 Entity / API-Key 页可带 query 跳入对应路由表详情。
